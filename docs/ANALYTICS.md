# 行为统计维护

演示站使用官网维护的共享协议和浏览器采集核心。数据写入官网 Worker 的 Cloudflare D1；热力图参考截图保存在私有 R2，分析补充页由 Cloudflare Access 保护。

完整口径与隐私见[官网访问分析](https://github.com/peach-mitao/peach-site/blob/main/docs/ANALYTICS.md)。静态回放与媒体读取继续使用原有链路，统计使用独立批量请求，不恢复动态 API 轮询。

## 同步与改版

- `scripts/sync_behavior.ts` 从官网复制 `browser/assets/behavior-contract.ts`、`browser/assets/behavior-core.ts` 和 `scripts/behavior_artifacts.ts`，记录来源提交与 SHA-256。草稿只用于预览，生产检查拒绝草稿或副本漂移。
- `browser/behavior-rules.ts` 维护演示站的功能标识。相同功能保留标识，新增语义使用新标识。避免以文字、CSS 位置和动态实体名称命名。
- 构建指纹包含浏览器源码、页面壳、公共构建入口和同步的应用资源。UI、按钮或样式变更后，需要为新指纹生成桌面和手机截图、元素边界与覆盖清单。
- 同步清单的提交号不参与布局指纹；共享 SDK 的实际源码参与指纹，来源与哈希仍由独立门槛校验。只更新工具或文档不会生成新的 UI 版本。
- 路由清单来自 `scripts/demo_pages.ts`。新增弹窗、条件按钮、主题或布局状态时，还须登记能打开该状态的捕获场景和行为回归；初始路由扫描不能证明未打开的弹窗已覆盖。
- `npm run behavior:check` 检查共用源码来源、当前构建指纹、全部登记路由、未映射控件与图片哈希；部署入口包含此检查。`PEACH_BEHAVIOR_ARTIFACTS` 可指定产物目录。
- `npm run behavior:capture -- <官网仓库目录> <演示站本地预览地址>` 使用对应官网提交的截图工具，生成两种视口的参考图。官网提交须与同步记录一致且工作区干净；截图与现有路由验收共用 `scripts/browser_state.ts` 的可见内容就绪判据。

采集脚本在构建时打包为带内容指纹的单个文件，使用不可变缓存。编辑模式与参考截图模式不采集。运行时未映射点击汇总用于发现遗漏，不自动把未知按钮归为已有功能。

规则优先采用语义属性。少量没有语义属性的按钮使用有限的静态文案或前缀匹配；修改其文案须同步规则并重新检查覆盖。动态实体名称和匹配到的文字不会进入访客事件。

官网和演示站共享匿名会话 Cookie，30 分钟无活动后更换。自有统计不包含输入、搜索内容、页面文字、完整 URL 或 IP；路径中的动态实体标识归一化。事件保留 30 天；“最后停留”表示最后观察到的位置。统计偏好入口位于演示提示中。
